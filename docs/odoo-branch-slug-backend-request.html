ZMall app ↔ Backend ↔ Odoo · Branch availability

Send the Odoo branch slug with the store, not from a hardcoded store ID map

Right now the app works out which Odoo branch a store belongs to by looking up the store's Mongo _id in a list hardcoded in the app. This page shows how that works today, why it breaks, and the one field the backend needs to add so the app can drop the list.

How it works today

Before checkout the cart calls POST http://196.191.117.85:9070/zmall_order/<branch_slug>. Odoo picks the branch only from that URL segment, matching it against pos.config.zmall_branch_slug. The app finds the slug in this order (resolveZmallBranchSlug in lib/utils/constants.dart):

1

Backend field store.zmall_branch_slug

Read from the store object of user_get_store_product_item_list. The app already checks this first, but the backend never sends it, so this step always misses.

Never sent
2

Hardcoded store ID map kZmallBranchSlugs

6aacf908ec395cd9bc9a18b9 → ayat, 6a856a07ea239cfe7a6d1eb7 → mexico. This is what actually resolves the slug today.

Used today
3

Store name contains a known slug

"Besh Mexico" contains "mexico". Only works for slugs already in the map, and only after store detail has loaded.

Fragile
4

Unresolved

Items have a pos_id but no slug was found. The check is skipped, logged as SKIPPED (NO BRANCH SLUG), and checkout stays open.

Silent skip

Why the store ID map is the wrong source

Store IDs differ between the test and production servers, and they change when a store is recreated. The map already has two commented-out older IDs for the same branches. Every new POS store needs an app release, and any store missing from the map silently loses its stock check, so customers can order items that are out of stock.

What the backend should change

Store the Odoo slug on the Zmall store record (for example a zmall_branch_slug field set by admin), and return it on the store object. The value must equal pos.config.zmall_branch_slug in Odoo exactly. Non-POS stores send null or omit it.

Request (unchanged) 
POST /api/user/user_get_store_product_item_list
{
  "store_id": "6a856a07ea239cfe7a6d1eb7"
}
Response (one field added) 
{
  "success": true,
  "store": {
    "_id": "6a856a07ea239cfe7a6d1eb7",
    "name": "Besh Mexico",
    "location": [9.0108, 38.7468],
    "is_provide_laundry_service": false,
    "zmall_branch_slug": "mexico"
  },
  "products": [ ... items with "pos_id" ... ]
}

The app reads this key as kZmallBranchSlugField = "zmall_branch_slug". No app change is needed for the cart to pick it up.

What happens after the field ships

Before

New POS store "Bole" → not in map → no slug → check skipped → out-of-stock items can be ordered. Fix needs an app release.

After

Admin sets zmall_branch_slug = "bole" on the store → backend returns it → app calls /zmall_order/bole → stock is checked. No app release.

Rollout

  1. Backend: add zmall_branch_slug to the store model and set it for Ayat and Besh Mexico on test.
  2. Backend: return it on every store object and on each order_list entry.
  3. App: check the debug screen shows source = backend for both stores.
  4. Backend: set the field on production stores.
  5. App: delete kZmallBranchSlugs, the name fallback, and isOdooStoreByName; read the slug only from the backend.
